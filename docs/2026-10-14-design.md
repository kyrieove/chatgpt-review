# chatgpt-review 已确认设计

用户于本轮确认：ChatGPT 主导拆任务、派发执行指令、审查证据并推进验收；名称改为 chatgpt-review。ChatGPT 默认只能读取当前聊天上传文件。执行端应兼容不同 Agent，双方均支持跨会话续接。

交付在项目内的新目录，保留 review-relay 原蓝本。通用 Markdown 协议是权威规则，Python 标准库工具只负责本地初始化与打包，不连接聊天平台。没有 Python 时，执行端按相同文件契约手动或用其可用工具生成包。

任务使用固定 task_id，审查使用递增 round 和唯一 package_id。每包独立包含当前源码范围、任务书、状态、测试报告、ChatGPT 续接摘要、使用说明、版本元数据与哈希。旧聊天、旧附件、本地绝对路径都不是下一会话的必要输入。

ChatGPT 区分本轮直接检查、执行端报告、推断及无法验证。缺材料先给收集任务；审查反馈绑定输入包，只在执行端核对当前状态后执行。修复沿用同一个 task_id。包不齐、证据不足及环境受限都不等于通过。

验收：skill 格式与引用有效；协议覆盖首次派发、上传审查、反馈修复、双方续接及停止条件；跨平台 CLI 在隔离夹具中完成初始化、两轮打包、哈希校验及敏感文件阻断；独立审查协议与运行结果。不进行全局安装或外部消息发送。

用户追加确认：skill 源码上传公开 Git 仓库，不生成 skill 发行 ZIP。开发任务的审查包继续使用 ZIP，增加显式源码与证据范围、历史摘要及压缩后硬预算；超预算拒绝生成新的最终包，不静默丢材料。新聊天仍可由每份独立包续接。公开仓库排除用户任务状态、开发审查包与缓存。

随后用户确认 ChatGPT 已连接其 GitHub 并能直接读取。v2 默认 GitHub Review，ZIP 为备用；同任务保持功能分支和同一 Draft PR，每轮绑定完整 SHA，增加 TEST_RESULTS 作为测试记录权威来源。执行端先完成本地准备、测试与拟推送历史的凭据扫描，有对应明确用户许可才远端写入。新会话重新读取 PR 版本与五份记录，工具无法核对版本时降级到固定版本文件或 ZIP。未自动合并、强推或覆盖。
