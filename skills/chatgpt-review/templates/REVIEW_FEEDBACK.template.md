# 审查反馈

- task_id：填写实际输入任务 ID。
- GitHub 输入：仓库、PR URL、完整 reviewed_head_sha、base SHA。ZIP 模式则不用此项。
- 输入 round：填写实际轮次。
- 输入 package_id：从当前附件 PACKAGE_INFO.json 读取。
- 实际检查范围：列出读过的文件与执行过的检查。
- 总体结论：等待材料、需要修复、等待验证或建议完成。

## 发现

| ID | 优先级与置信度 | 文件位置 | 触发条件与影响 | 证据来源与内容 | 修法与验收 |
|---|---|---|---|---|---|
| F-001 | 按事实填写 | 核实相对路径和行号 | 描述具体行为 | DIRECT、REPORTED、INFERRED 或 UNVERIFIED | 最小修改方向与可观察结果 |

没有发现时删除示例行，说明审查范围与限制。

同一发现记录已尝试的轮次与结果。连续两轮未改善时，下一轮改为诊断任务，列出已否定假设、需要的证据和判断条件。

## 验收判断

逐项对应 TASK_BRIEF 的验收 ID，区分 ChatGPT 本轮检查与执行端报告。无法检查的项保留 BLOCKED 或 NOT RUN。

## 可直接转交执行端

继续 task_id：填写实际 ID。
本反馈对应输入 round 与 reviewed_head_sha 或 package_id：填写实际身份。
先核对本地代码与该版本是否一致，保存当前新改动。处理仍适用且已授权的发现，保存反馈原文、决定与证据。
允许修改范围：填写范围。
需处理发现与验收：填写具体任务。
下一轮：填写递增轮次。更新同一任务的五份记录，测试细节存入 TEST_RESULTS。默认在同一功能分支修复，已有对应明确许可才推送和更新同一 Draft PR，返回 URL 与 head SHA；否则停在本地，必要时生成安全备用包。

## 给新 ChatGPT 聊天的续接摘要

输出可独立理解的目标、决定、输入包身份、未决发现、已检查范围与下一步。如果执行端尚未保存到新包，用户需同时上传本反馈与最新可用 ZIP。
